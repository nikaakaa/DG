# DG 架构设计指南

> 2D 格子涌现式沙盒 PvPvE 游戏，服务端权威，C# (Fantasy) + Unity

---

## 核心原则

**组合大于继承。** Entity 是空壳，Component 和 Tag 描述它，System 执行规则。不按物体类型创建专属 Handler。

```
墙       = Entity + Tags(Entity.Structure.Wall, Material.Stone) + HealthComponent + BlockingComponent + PushableComponent
推进器    = Entity + Tags(Entity.Device.Thruster, Material.Metal) + ActivatableComponent + FacingComponent
传送带    = Entity + Tags(Entity.Device.Conveyor, Material.Metal) + ConveyorComponent + FacingComponent
玩家     = Entity + Tags(Entity.Player, Faction.Player, Material.Organic) + HealthComponent + PlayerControlComponent
燃烧中    = Tag(State.Burning) + BurningComponent
```

**核心架构词汇：World 保存世界状态，Entity 是世界对象，Component/Tag 描述实体，Command 表达外部意图，System 负责游戏规则，Query 负责只读查询，Result 表达执行结果，Event 表达已发生事实，Dirty 表达待同步变化，Fantasy Handler 只留给网络入口。**

---

## 一、核心词汇

| 名称 | 职责 | 例子 |
|------|------|------|
| `World` | 保存权威世界状态、空间索引和 dirty 记录 | entity 注册、移动、删除、chunk/cell |
| `Entity` | 世界对象壳子 | 玩家、墙、传送带、怪物 |
| `Component` | 能力和状态数据 | `HealthComponent`, `BlockingComponent`, `StickyComponent` |
| `Tag` | 语义分类和规则筛选条件 | `Entity.Player`, `Faction.Hostile`, `State.Burning` |
| `Command` | 外部意图 | `MoveCommand`, `PlaceCommand`, `InteractCommand` |
| `System` | 执行游戏规则，读取 Component/Tag，修改 World | `MovementSystem`, `PlacementSystem`, `BurningSystem` |
| `Query` | 统一只读查询世界 | `HasBlockingAt`, `AllWithTag`, `GetEntitiesAt` |
| `Result` | 一次 Command 的执行结果 | `MoveResult`, `PlaceResult` |
| `Event` | 已经发生的事实通知（Fantasy EventComponent） | `EntityMovedEvent`, `EntityDestroyedEvent` |
| `Dirty` | 需要同步、刷新或保存的变化 | changed cells, changed entities |
| `Fantasy Handler` | 网络消息入口 | `C2G_MoveRequestHandler`, `C2G_JoinWorldRequestHandler` |

核心调用链：

```
Fantasy Handler / AI / Scheduler / Editor
    -> Command
    -> System.Execute(world, command)
    -> Query 读取世界
    -> World 修改状态
    -> Result 返回调用者
    -> Event 通知已发生事实
    -> Dirty 记录待同步变化
    -> SyncSystem 批量广播
```

网络入口只负责协议和 Session：

```
C2G_MoveRequestHandler
    -> 校验 Session 与 player entity 绑定
    -> 创建 MoveCommand
    -> MovementSystem.Execute(world, command)
    -> 写入 G2C_MoveResponse
    -> 成功时让 Dirty/SyncSystem 负责后续同步
```

游戏规则不写在 Fantasy Handler 里。Fantasy Handler 是壳，World/System 是规则核心。

## 二、Entity、Component 与 Tag

### Entity

```csharp
public class Entity
{
    public int Id;
    public Vector2Int Coord;

    private readonly List<IComponent> ComponentList = new();
    private readonly Dictionary<Type, IComponent> ComponentDict = new();
    private readonly TagSet Tags = new();

    public void Add<T>(T component) where T : IComponent;
    public T Get<T>() where T : class, IComponent;
    public bool Has<T>() where T : class, IComponent;
    public void Remove<T>() where T : class, IComponent;
    public void AddTag(WorldTag tag);
    public bool HasTag(WorldTag tag);
    public bool HasAnyTag(ReadOnlySpan<WorldTag> tags);
    public bool HasAllTags(ReadOnlySpan<WorldTag> tags);
    public void RemoveTag(WorldTag tag);
}
```

Entity 没有类型枚举、没有继承层次。它是什么，由 Tag 表达；它能做什么，由 Component 表达。

### Tag 与 Component 的边界

Tag 表达实体的语义分类、阵营、材质、临时状态标记和规则筛选条件。Component 表达能力、状态数据和会参与结算的规则数据。

| 适合 Tag | 适合 Component |
|----------|----------------|
| `Entity.Player` | `PlayerControlComponent` |
| `Entity.Structure.Wall` | `HealthComponent`, `BlockingComponent` |
| `Entity.Device.Conveyor` | `ConveyorComponent`, `FacingComponent` |
| `Faction.Hostile` | `AIComponent` |
| `Material.Metal` | `DurabilityComponent` |
| `State.Burning` | `BurningComponent` |

判断标准：

| 问题 | 归属 |
|------|------|
| 只是分类、筛选、阵营、材质、语义状态？ | Tag |
| 有数值、有生命周期、参与移动/伤害/放置/同步结算？ | Component |
| 需要被 System 修改？ | Component |
| 只是让 AI、编辑器、查询系统识别？ | Tag |

### 基础组件

| 组件 | 数据 | 用途 |
|------|------|------|
| `HealthComponent` | Current, Max | 有血量的东西：墙、玩家、怪物 |
| `StickyComponent` | GroupId | 粘液块：相邻同 GroupId 推动时一起移动 |
| `BlockingComponent` | 无数据 | 阻挡移动和放置 |
| `FacingComponent` | Direction | 朝向：推进器、传送带需要方向 |
| `ActivatableComponent` | Active, Cooldown | 可激活：推进器 |
| `ConveyorComponent` | Speed | 传送带：固定 tick 向 Facing 方向传递物品 |
| `PushableComponent` | 无数据 | 可被推动 |
| `BurningComponent` | TicksRemaining, DamagePerTick | 着火：固定 tick 对有 HealthComponent 的实体造成伤害 |
| `PlayerControlComponent` | PlayerId | 玩家控制：接收输入 |

### 推荐 Tag 分类

```
Entity.Player
Entity.Monster
Entity.Structure
Entity.Structure.Wall
Entity.Device
Entity.Device.Conveyor
Entity.Device.Thruster
Entity.Hazard
Entity.Projectile

Faction.Player
```

Tag 不替代 Component。`State.Burning` 可以让 UI、AI、过滤器识别燃烧状态，真正的剩余时间和伤害仍在 `BurningComponent`。

## 三、World

World 是状态容器和统一修改入口。它保存空间数据、实体索引和 dirty 记录，但不直接承载网络 Session，也不直接解析客户端协议。

```csharp
public sealed class World
{
    private readonly ChunkStore Chunks = new();
    private readonly EntityTracker EntityTracker = new();
    private readonly DirtyTracker DirtyTracker = new();

    public WorldQuery Query { get; }

    public bool AddEntity(Entity entity, Vector2Int coord);
    public bool RemoveEntity(Entity entity);
    public bool MoveEntity(Entity entity, Vector2Int target);
    public bool TryGetEntity(int entityId, out Entity entity);
    public void MarkCellDirty(Vector2Int coord);
    public void ClearDirty();
}
```

`World.MoveEntity` 是底层状态修改，不负责移动规则。移动是否合法、是否推动、是否触发传送带，由 `MovementSystem` 判断。

服务端 World 必须是纯 C#。Unity 客户端可以使用 `Vector2Int`，服务端权威 World 不依赖 `UnityEngine`。

## 四、Query

Query 是只读世界查询接口。System 通过 Query 理解世界，不直接翻 World 内部字典。

```csharp
public sealed class WorldQuery
{
    private readonly World world;

    public bool HasBlockingAt(Vector2Int coord);
    public bool HasEntityWith<T>(Vector2Int coord) where T : class, IComponent;
    public bool HasTagAt(Vector2Int coord, WorldTag tag);
    public IEnumerable<Entity> GetEntitiesAt(Vector2Int coord);
    public IEnumerable<Entity> GetEntitiesWith<T>(Vector2Int coord) where T : class, IComponent;
    public IEnumerable<Entity> GetEntitiesWithTag(Vector2Int coord, WorldTag tag);
    public IEnumerable<Entity> AllWith<T>() where T : class, IComponent;
    public IEnumerable<Entity> AllWithTag(WorldTag tag);
    public bool CanOccupy(Entity mover, Vector2Int coord);
}
```

Query 不修改 World，不发 Event，不记录 Dirty。

## 五、Command、System、Result 与 Event

Command 表示外部意图，System 执行世界规则，Result 返回执行结果，Event 表示已经发生的事实。

| 名称 | 是否修改 World | 职责 |
|------|----------------|------|
| `Command` | 否 | 表达“想做什么” |
| `System` | 是 | 执行规则并修改 World |
| `Result` | 否 | 告诉调用者成功、失败、最终状态和原因 |
| `Event` | 否 | 通知其他系统“已经发生什么” |

```csharp
public readonly struct MoveCommand
{
    public readonly int EntityId;
    public readonly Vector2Int Target;
    public readonly CommandSource Source;
}

public readonly struct MoveResult
{
    public readonly bool Success;
    public readonly int EntityId;
    public readonly Vector2Int FinalCoord;
    public readonly MoveErrorCode ErrorCode;
}

public sealed class MovementSystem
{
    public MoveResult Execute(World world, MoveCommand command)
    {
    }
}
```

Command 和 Event 的区别：

```
MoveCommand      = 外部想让实体移动
MoveResult       = 这次移动请求的执行结果
EntityMovedEvent = 实体已经被移动
```

Event 不负责取消操作。是否允许执行，由 System 在返回 Result 前判断。

## 六、System

System 是游戏规则执行者。它读取 Component/Tag，通过 Query 判断世界，修改 World，返回 Result，必要时发布 Event。

| System 类型 | 触发来源 | 例子 |
|-------------|----------|------|
| `CommandSystem` | 玩家、AI、机关、测试提交 Command | `MovementSystem`, `PlacementSystem`, `InteractionSystem` |
| `FixedTickSystem` | 服务端或客户端固定 tick | `BurningSystem`, `CooldownSystem`, `ConveyorSystem`, `AISystem` |
| `PostCommandSystem` | 某个 Command 成功后结算副作用 | `HealthDeathSystem`, `AttachmentCleanupSystem` |
| `SyncSystem` | 固定同步间隔或 dirty flush | `WorldSyncSystem`, `DirtyFlushSystem` |

移动系统示例：

```csharp
public sealed class MovementSystem
{
    public MoveResult Execute(Scene scene, World world, MoveCommand command)
    {
        if (!world.TryGetEntity(command.EntityId, out Entity entity))
            return MoveResult.UnknownEntity(command.EntityId);

        if (!world.Query.CanOccupy(entity, command.Target))
            return MoveResult.Blocked(entity.Id, entity.Coord);

        Vector2Int from = entity.Coord;
        world.MoveEntity(entity, command.Target);
        world.MarkCellDirty(from);
        world.MarkCellDirty(command.Target);
        scene.EventComponent.Publish(new EntityMovedEvent(entity.Id, from, command.Target));
        return MoveResult.Success(entity.Id, command.Target);
    }
}
```

传送带不是 `ConveyorHandler`。传送带是 `Entity.Device.Conveyor` tag 加 `ConveyorComponent` 和 `FacingComponent`，由 `ConveyorSystem` 在固定 tick 中生成 `MoveCommand`，再交给 `MovementSystem`。

## 七、Event（Fantasy EventComponent）

不自己造事件总线，直接用 Fantasy 框架的 `EventComponent`。

### 发布事件

```csharp
scene.EventComponent.Publish(new EntityMovedEvent(entity.Id, from, to));
```

### 订阅事件

继承 `EventSystem<T>`，写 `Handler`：

```csharp
// 服务端：死亡后掉落
public sealed class OnEntityDestroyed : EventSystem<EntityDestroyedEvent>
{
    protected override void Handler(EntityDestroyedEvent e)
    {
        DropLoot(e.EntityId);
    }
}

// 客户端：播放音效
public sealed class OnEntityMovedFX : EventSystem<EntityMovedEvent>
{
    protected override void Handler(EntityMovedEvent e)
    {
        AudioManager.PlayFootstep(e.To);
    }
}
```

### 事件定义

Event 是已发生事实的通知，不是意图，也不是返回值。

```csharp
public readonly struct EntityMovedEvent
{
    public readonly int EntityId;
    public readonly Vector2Int From;
    public readonly Vector2Int To;
}

public readonly struct EntityDamagedEvent
{
    public readonly int EntityId;
    public readonly int Damage;
    public readonly int CurrentHealth;
}

public readonly struct EntityDestroyedEvent
{
    public readonly int EntityId;
}
```

### 服务端 vs 客户端

同一套 `EventComponent` 基础设施，两边订阅不同事件、做不同事：

| | 服务端 | 客户端 |
|---|---|---|
| 订阅什么 | 全部事件 | 只关心表现相关事件 |
| 做什么 | 规则结算、连锁反应、掉落 | 音效、特效、UI 更新 |
| 例子 | `EntityDestroyedEvent` → 掉落物、清理附着 | `EntityMovedEvent` → 播放脚步声 |

### Before 事件 vs After 事件

用不同的 event struct 区分，不靠框架机制：

| | Before 事件 | After 事件 |
|---|---|---|
| 时机 | 动作**发生前** | 动作**完成后** |
| 能力 | 可设置 `Cancelled = true` 拦截 | 纯通知，不可修改 |
| 例子 | `BeforeMoveEvent` — 禁锢buff拦截移动 | `EntityMovedEvent` — 通知已移动 |
| 谁发 | System 在执行前 `Publish` | System 在执行后 `Publish` |

```csharp
// Before: 在 System 执行前发布，订阅者可拦截
var before = new BeforeMoveEvent(entity.Id, from, to);
scene.EventComponent.Publish(before);
if (before.Cancelled) return MoveResult.Cancelled;

// ... 执行移动 ...

// After: 执行后通知
scene.EventComponent.Publish(new EntityMovedEvent(entity.Id, from, to));
```

需要等待结果时，不用 Event 表达，直接读取 Result。

## 八、Dirty 与同步

Dirty 记录 World 中被改变的 cell、entity、chunk。它不是玩家视野，不是广播对象列表，也不是规则结果。

| 数据 | 含义 |
|------|------|
| `ChangedCells` | 哪些格子发生变化 |
| `ChangedEntities` | 哪些实体状态发生变化 |
| `ChangedChunks` | 哪些 chunk 需要刷新或保存 |

同步循环只读取 Dirty 和可见性结果：

```
SyncSystem
    -> 读取 DirtyTracker
    -> 按 observer 视野过滤
    -> 生成 G2C_EntityMovedNotify / snapshot / despawn
    -> 广播给对应 Session
    -> ClearDirty()
```

Dirty 是全局变化记录，AOI/Visibility 是面向观察者的过滤结果，两者不要混在一起。

## 九、三段循环架构

命令处理、固定 tick 和网络同步是三个独立阶段。

```
┌──────────────────────────────────────────────────┐
│  命令与规则循环                                      │
│                                                  │
│  玩家网络输入 -> Fantasy Handler -> Command        │
│  服务端 AI    -> Command                          │
│  机关/定时器   -> Command                          │
│                       │                          │
│                       ▼                          │
│                 System.Execute()                 │
│                       │                          │
│        Query -> World 修改 -> Result              │
│                       │                          │
│              Event + Dirty                       │
└──────────────────────────────────────────────────┘
                    │
                    ▼
┌──────────────────────────────────────────────────┐
│  固定 Tick 循环                                      │
│                                                  │
│  BurningSystem                                    │
│  CooldownSystem                                   │
│  ConveyorSystem                                   │
│  AISystem                                         │
│                                                  │
│  时间型规则只在固定 tick 中推进                     │
└──────────────────────────────────────────────────┘
                    │
                    ▼
┌──────────────────────────────────────────────────┐
│  同步循环                                           │
│                                                  │
│  读取 Dirty                                        │
│  按 observer 视野过滤                              │
│  批量广播                                          │
│  清空 Dirty                                        │
│                                                  │
│  只管同步，不推进规则                               │
└──────────────────────────────────────────────────┘
```

燃烧、冷却、AI、传送带这类时间型规则不能跟玩家输入次数绑定。玩家一秒发十次移动请求，不应该让燃烧快十倍。

## 十、同格多实体与互斥

没有层、没有槽位、没有互斥声明。互斥是 System 里的规则，不是数据结构。

```csharp
public sealed class PlacementSystem
{
    public PlaceResult Execute(Scene scene, World world, PlaceCommand command)
    {
        if (world.Query.HasBlockingAt(command.Coord))
            return PlaceResult.Blocked(command.Coord);

        world.AddEntity(command.Entity, command.Coord);
        scene.EventComponent.Publish(new EntityPlacedEvent(command.Entity.Id, command.Coord));
        return PlaceResult.Success(command.Entity.Id, command.Coord);
    }
}
```

同一个格子可以同时有传送带、掉落物、火焰、触发器。具体能否共存，由 `PlacementSystem`、`MovementSystem`、`InteractionSystem` 读取 Component/Tag 后判断。

## 十二、命名禁区

为了避免概念混乱，当前阶段不使用这些顶层概念：

| 不使用 | 原因 | 替代 |
|--------|------|------|
| `BlockHandler` | 会把规则重新绑定到物体类型 | `Command + System` |
| `WallHandler` | 会回到每种物体一个类 | `Tag + Component + System` |
| `ConveyorHandler` | 传送带是能力组合，不是专属入口 | `ConveyorSystem` |
| `Rule` | 和 System 职责重叠 | 规则逻辑写在 System |
| `InputProcessor` | 容易只想到玩家输入 | `CommandProcessor` 或直接调用 System |
| `MovementIntent` | 和 Command 重复 | `MoveCommand` |

`Handler` 只留给 Fantasy 网络消息入口。

## 总结

### 核心分工

| 名称 | 一句话 |
|------|--------|
| `World` | 保存世界状态 |
| `Entity` | 世界对象 |
| `Component` | 能力和状态数据 |
| `Tag` | 语义分类和筛选条件 |
| `Command` | 外部意图 |
| `System` | 游戏规则执行者 |
| `Query` | 只读世界查询 |
| `Result` | 执行结果 |
| `Event` | 已发生事实 |
| `Dirty` | 待同步变化 |
| `Fantasy Handler` | 网络入口 |

### 核心调用链

```
外部输入
    -> Fantasy Handler / AI / Scheduler / Editor
    -> Command
    -> System.Execute(world, command)
    -> Query 读取 Component/Tag/空间状态
    -> World 修改 entity/cell/chunk
    -> Result 返回调用者
    -> Event 通知已发生事实
    -> Dirty 累积变化
    -> SyncSystem 按视野批量广播
```

这套命名的核心约束：**Handler 不写游戏规则，System 不处理网络协议，Command 不是 Event，Tag 不替代 Component，Dirty 不等于同步对象列表。**
