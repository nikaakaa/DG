# Design: 权威世界调试工具

## Context
当前权威移动链路已经以服务端 `GameWorld` 为唯一状态源，客户端通过 snapshot/delta 建立镜像。`GameWorld.RemoveEntity` 已经能从共享世界移除实体，但 `WorldDelta` 目前只包含仍然存在的变更实体；实体被删除后没有明确的 removed id 传给客户端。

调试工具如果直接修改客户端 `ClientMapWorld`，只能验证本地显示，无法证明服务端规则、多客户端同步和后续组件组合正确。因此本变更把建造、拖拽和删除都设计为服务端权威调试命令。

## Goals
- 让服务端删除实体可以通过统一 WorldDelta 同步到客户端。
- 让 Unity Demo 可以在 Play Mode 中通过 Runtime 调试 UI 建造、拖拽和删除实体。
- 让所有调试编辑结果来自服务端权威 `GameWorld`，并通过现有 observer 广播给在线客户端。
- 用最小调试权限开关防止普通运行模式暴露世界编辑命令。

## Non-Goals
- 不实现正式账号、登录、Token、GM 角色或数据库权限。
- 不实现正式玩家建造系统、背包、资源消耗、建造距离、冷却或拥有权规则。
- 不实现地图资源持久化，不把编辑结果写回 Luban 表格或场景资产。
- 不实现复杂 AOI、预测、回滚、插值或编辑历史撤销。
- 不把调试拖拽建模为普通玩家移动；拖拽是调试传送。

## Decisions

### 删除同步进入 WorldDelta
删除是世界状态变化的一部分，应和 changed entity 使用同一个 `G2C_WorldDeltaNotify` 广播边界。协议中增加 `RemovedEntityIds`，客户端收到后先删除镜像实体，再应用变更实体，避免同一 delta 中出现删除和重建时的顺序歧义。

### 调试命令走独立 RPC
建造、拖拽和删除不复用 `C2G_MoveRequest`。普通移动会经过移动规则、占位阻挡和玩家归属校验；调试拖拽需要表达“强制设置坐标”，建造和删除也不是移动语义。

### 调试权限先使用服务端开关
当前阶段不引入完整鉴权系统。服务端先提供一个开发期开关，例如 `DebugWorldEditEnabled`。所有调试编辑 Handler 的第一步都检查该开关，关闭时返回失败且不修改 `GameWorld`。

### 客户端工具只发意图
Unity 调试工具负责拾取格子、选择实体、展示 ghost/选中状态和发送请求；它不直接修改权威坐标。服务端响应或广播到达后，客户端再通过 `ClientWorldRunner` 应用 snapshot/delta。

### UI 先按调试 hotbar 形态实现
第一版 UI 使用 Play Mode Runtime 面板，而不是 EditorWindow。面板提供底部快捷栏和少量快捷键，使调试操作接近游戏内创造模式的手感，但协议和服务端语义仍然保持 Debug/Admin 命令。快捷栏至少包含阻挡体、球、传送带、拖拽和删除；`R` 用于旋转当前建造方向，数字键用于切换槽位，鼠标左键执行当前工具。

## Risks
- 如果删除 delta 没有测试覆盖，观察客户端可能残留已删除实体。
- 如果调试开关默认开启，世界编辑命令可能在非调试运行中被误用。
- 如果客户端工具直接本地修改世界，手动测试会误判端到端同步已经成功。
